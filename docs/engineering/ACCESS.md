# 国内访问与弱网记录

记录日期：2026-09-15。目标：`https://ai-guide.yomexa.com/`。这是一次验收快照，不是实时可用性承诺。

## 当前决定

保留 GitHub Pages 自定义域名，Cloudflare 的 `ai-guide` CNAME 恢复为仅 DNS。试用 Cloudflare 全球代理后，移动线路成功数下降，未继续保留该入口。没有购买服务或修改其他子域名。

国内稳定直连仍未完成。后续优先根据已有备案和托管条件选择国内静态托管／CDN；没有相应条件时评估面向大陆的香港线路。先在测试入口验证三网效果，再迁移正式域名。不会要求读者先安装 VPN 才能阅读本站教程。

## 国内节点对比

来源：[ITDog 网站测速](https://www.itdog.cn/http/)。实际输入本站完整 HTTPS 地址，选择中国电信、中国联通、中国移动，关闭港澳台与海外节点，执行快速测试。以下时间为结果采集时间（北京时间），并非所有节点同时开始或结束。

| 配置 | 采集时间 | HTTP 200／节点总数 | 成功比例 | 成功节点平均耗时 |
| --- | --- | --- | --- | --- |
| GitHub Pages 直连，运营商 DNS | 22:15:52 | 236／262 | 90.1% | 1.577 秒 |
| Cloudflare 代理，运营商 DNS | 22:28:23 | 221／260 | 85.0% | 1.637 秒 |
| Cloudflare 代理，指定 DNS 223.5.5.5 | 22:29:54 | 227／259 | 87.6% | 2.099 秒 |
| 恢复仅 DNS 后，运营商缓存传播中 | 22:35:28 | 223／258 | 86.4% | 1.417 秒 |

平均耗时沿用检测平台的成功请求口径，失败不计入，因此不能仅比较平均值判断改善。在线节点数量动态变化，不是严格同时、完全相同网络条件下的实验。

| 运营商 | 原入口成功／总数 | 代理＋运营商 DNS | 代理＋指定 DNS |
| --- | --- | --- | --- |
| 电信 | 80／86 | 75／84 | 80／83 |
| 联通 | 70／85 | 80／85 | 82／85 |
| 移动 | 86／91 | 66／91 | 65／91 |

原入口全部解析至 GitHub Pages。代理后的运营商 DNS 一轮中，167 个节点使用 Cloudflare IP，92 个仍使用 GitHub IP，1 个解析失败；指定 DNS 一轮中，252 个使用 Cloudflare，6 个仍使用 GitHub，1 个解析失败。因此两轮都不能称作纯 Cloudflare 全量测试。

指定 DNS 的 259 个节点名称都能在原入口一轮中匹配：相同名称节点的成功数从 234 降为 227。其中明确解析到 Cloudflare 的移动节点为 86 个，只有 61 个成功。两轮均出现上海4、北京8、江苏南京4、浙江嘉兴、福建福州2、辽宁沈阳等移动节点失败；故撤回代理，而非将改善联通的结果推广至全部网络。检测点名称只用于匹配平台记录，不代表整个城市的全部线路。

HTTP 200 只验证首页请求，不执行所有 JavaScript、不代表完成课程、不证明第三方官网可达，也不计作真人学习反馈。DNS 缓存会使切换后的实际入口暂时混合；配置保存后还需核对公共解析与实际响应头。

回退后，公共 DNS `1.1.1.1` 和 `223.5.5.5` 已恢复解析至 GitHub，显式绕过请求代理的首页请求返回 `Server: GitHub.com` 和 HTTPS 200。但最后一轮运营商节点仍有 77 个使用缓存的 Cloudflare IP、180 个使用 GitHub、1 个解析失败；总计 35 个未成功，不能将原入口的 90.1% 当作回退后的实时成功率。传播期结果已单独列出，不用反复重测挑选最好数字。

## 应用层优化与验收

- 站内脚本、样式、图片、排名快照和练习材料均由本站提供，访问统计脚本异步加载。
- 主程序无法下载时，静态首页仍提供三条主线和全部独立教程入口；这些正文不依赖 React 主程序。
- 正文模块加载失败时，故障页可以直接进入阅读目录，并保留重新加载按钮。
- 在本地生产预览阻断统计服务、主程序、正文模块分别验证了以上路径；主程序失败时检查 1440、768、320 像素宽度，无横向溢出。实际点击豆包和阅读目录均可打开独立正文。浏览器阻断及视口设置已恢复。
- 线上新首页已包含兜底内容和异步统计，统计脚本只有一份。Cloudflare 试用期间，显式指定两个已解析边缘 IP 的 HTTPS 请求均返回 200；主脚本在同一边缘入口第二次请求命中缓存。这仅证明代理可工作，不能抵消国内移动节点的退步。
- 回退后本机绕过请求代理验证首页、三篇独立主线、阅读样式、练习材料和排名状态 JSON，七个地址均返回 200。正式浏览器的首页→豆包正文、完整排名及反馈页可打开，未发现该正式站点的控制台错误；浏览器验证不作为国内直连证据。

仍有约 504 KB（gzip 约 167 KB）的主程序构建提示；没有通过放宽阈值掩盖。当前阅读兜底能缓解下载失败，不能解决线路本身不可达。国内正式托管选型完成后，再按真实首屏耗时决定后续拆包范围。

## 复测方式

沿用相同域名、运营商选择、DNS 设置和 HTTP 请求方式，记录检测日期、节点名称、响应 IP、状态及耗时；分别统计成功与失败。切换入口后先检查 DNS 缓存，必要时单独记录指定 DNS 的排查结果，不与正常运营商解析混为一组。

本机请求使用明确绕过请求代理的 HTTPS 方式，保持证书校验。本轮本机有系统代理设置，因此只把显式绕过代理的命令作为本机直连证据；国内访问范围主要依据上面的第三方三网节点。真实手机／家庭宽带的完整阅读仍待验收。
