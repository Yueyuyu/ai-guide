# 质量检查与验收

## 自动检查

统一运行 `pnpm check`，任一步失败即停止：

1. `pnpm test`：Node 内置测试，覆盖目录、状态、来源、练习、排名及阅读页。
2. `pnpm audit:content`：检查课程、路线、章节与本地资源。
3. `pnpm audit:docs`：检查当前维护文档的本地链接和机器专属路径。
4. `pnpm build`：实际编译互动站和独立 HTML。

默认检查不调用第三方产品账号、不联网刷新榜单、不执行浏览器操作。外链审计单独运行，不能把网络抖动当作课程逻辑失败。

GitHub Actions 在 Linux 和 Windows 上执行上述流程；工作流配置成功不代表远程执行已经通过，结果以推送后的 Actions 记录为准。

## 按改动选择回归

| 改动 | 至少检查 |
| --- | --- |
| 课程文案与来源 | 内容审计、独立阅读页、对应来源记录 |
| 新课程或路线顺序 | 课程引用、下一课、已完成进度、选学处理 |
| localStorage 或备份格式 | 老备份、无效输入、损坏原数据、导入合并与草稿冲突 |
| 教程组件 | 正文、复制、求助、保存、目录、键盘焦点 |
| 品牌或卡片 | 原色、缺图、小屏文字、分类与公司归属 |
| 排名 | 原始精度、并列、筛选、加载、失败保留和方法说明 |
| 发布配置 | 根目录及子目录资源、独立正文、canonical 与 sitemap |

## 浏览器验收

优先使用已有浏览器工具；不可用时记录错误与替代方式，不宣称未执行的检查通过。生产预览可使用 4190，独立浏览器配置隔离测试数据。

基本路径：

- 首页 → 路线 → 教程 → 复制材料 → 填写成果 → 下载 → 我的成果 → 刷新恢复。
- Codex 创建 → 修改 → 验收，下一课携带正确路线上下文。
- 工具目录 → 公司 → 网页／桌面对应教程，产品与模型不混淆。
- 榜单 → 指标与范围 → 配置详情 → 来源或学习入口。
- 独立目录 → 无 JavaScript 正文 → 回到互动版对应章节。

桌面至少检查 1440，平板 768，手机 390 与极窄 320。检查页面身份、真实正文、无框架错误遮罩、控制台、图片、整页溢出和关键交互。页面采用按需加载，等待目标页的确切标题出现，避免把上一页或加载瞬间当成结果。

截图与临时测试脚本默认保存在项目外。新增组件行为需要验证；普通文案或样式调整不为凑数量编写镜像测试。

## 真实产品实测

网站交互通过与豆包／Codex 内的任务成功是不同层面的证据。账号内实测记录：

| 项目 | 要记录什么 |
| --- | --- |
| 环境 | 日期、系统、产品版本或界面范围、登录状态 |
| 准备 | 官方入口、账号条件、实际工作目录 |
| 操作 | 发送、追问、生成／文件写入、复制或导出 |
| 核对 | 实际结果、失败表现、与教程不同的步骤 |
| 证据 | 脱敏截图或操作记录，明确未测范围 |

没有账号或无法完成操作时保留“未实测”，不能把人工示例改称工具生成结果。新手可用性测试还需真实参与者独立操作，自动化不能代替。

## 交付记录

最终说明应包含：改了什么、执行了哪些检查、有效结果、证据位置、仍未验证的部分。已有历史记录保持原日期，不复制旧结论充当新结果。阶段状态见[STATUS.md](../STATUS.md)。
