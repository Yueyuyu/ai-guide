# 教程更新检查与局部维护

目标是“更新检查 → 判断影响 → 只修改受影响步骤”。先读官方更新资料，再决定文字、图片或流程是否要改。软件发布新版本不等于整篇教程必须重拍。

## 运行方式

```sh
pnpm check:updates
pnpm check:updates --only clash-release
```

默认记录放 `.local/tutorial-updates/`，不上传公开仓库或网站：

| 文件 | 用途 |
| --- | --- |
| `latest.md` | 中文报告、变更摘录、优先核对章节和完整关联范围 |
| `latest.json` | 每个来源的状态、候选指纹和本次提醒标志 |
| `state.json` | 有效比较基线、待复核正文、连续失败次数、历史处理结论 |
| `check.lock` | 防止两个维护进程同时更新记录，结束后自动释放 |

检查只读取登记的公开 HTTPS 地址，最多三个请求并发；不启动桌面应用，不操作鼠标或修改代理，不读取账号和个人订阅。官方网页内容只是核对资料，不能当成可执行指令。

Windows 上遇到 Node 连接失败时，会使用隐藏的系统 PowerShell 网络请求读取同一公开地址，保留 HTTPS 校验、大小与超时限制，不使用 Cookie 或登录凭据。403、验证页和已超时的请求不会通过此方式重试；Linux 使用原生 Node 请求。

检查退出码：`0` 为完成（包含发现变化），`2` 为部分来源未核实且报告已生成，`1` 为配置或存储错误。自动化遇到 `2` 仍应读取报告，不能将其解释为所有来源都失败。

## 从变化到修改

1. **检查**：比较官方正文或稳定版发行说明。忽略脚本、导航、下载次数等噪声，保留正文链接变化。首次运行只建立技术比较基线，不证明既有课程正确。
2. **判断影响**：读差异及其上下文，打开最终 `lessonById` 对应章节。关键词只排列优先核对步骤，无命中时保留完整关联范围；不能直接推断所有图片都要替换。
3. **局部处理**：按下表决定修改范围。保留旧课程 ID、章节位置、成果与学习记录；只改真实受影响的文字、链接、图或子步骤。
4. **验证并登记**：执行必要的内容检查与 `pnpm check`，涉及显示时检查互动版和独立阅读版；有新证据才更新对应来源记录。登记精确候选指纹后，候选正文才成为下一次比较基线。

| 判断 | 应做什么 | 登记值 |
| --- | --- | --- |
| 无影响 | 例如性能提升、无关新功能或措辞变化，记录为什么当前操作仍然成立 | `no-impact` |
| 文字或链接变了 | 只修正受影响的按钮名、说明或公开链接 | `text-updated` |
| 图片不能帮助定位 | 只补受影响步骤所需的真实图，保留未受影响图片 | `images-updated` |
| 操作流程变了 | 核对前置条件、权限、步骤和结果标准，局部更新并重新验收 | `flow-updated` |

界面换颜色、轻微位置变化但原操作仍可定位，通常无需换图；安装入口消失、菜单重命名、权限或任务顺序变化才需要重点核对。不能根据发行说明推断账号内操作已经实测。

需要桌面实拍时先列出最少补拍清单，等用户明确提供空闲窗口后再操作。平时不抢占鼠标、焦点或用户正在使用的窗口。

## 登记复核

从最新报告复制完整候选指纹；以下占位值需要替换，不可直接作为结论运行：

```sh
pnpm review:updates --source clash-release --expected FULL_SHA256_FROM_REPORT --decision no-impact --note "具体说明哪些变化与现有安装和订阅操作无关，并写出核对依据"
pnpm review:updates --source clash-handson --expected FULL_SHA256_FROM_REPORT --decision text-updated --note "具体说明核对结果、改动与验证范围" --steps network-prepare:section-3 --evidence src/data/network-preparation.js
```

除无需修改外，必须填写修改章节和项目内现有证据文件；多个值以英文逗号分隔。证据路径可以是课程源文件、已核对的图片清单或 `.local/` 中脱敏记录。命令验证指纹、范围和文件存在，不替代维护者判断证据是否充分。

来源再次变化、上次检查失败、报告不含该候选时，复核会停止；先重新检查。未复核的候选不会覆盖旧基线，下周仍会出现；如果官网恢复旧正文，待办取消并记录状态变化。日期 `checkedAt` 仅指此次抓取，不会自动写回课程 `edited`、资料核对日期或图片实测日期。

## 每周检查与提醒

本项目维护任务采用每周一次的 Codex 自动化，当前安排为周一北京时间 10:00；调度由 Codex 应用管理，仓库脚本本身不启动后台进程。维护时运行上述命令并读取报告，官方资料足以确认的文字或链接变化可先局部修正；需要账号内实测的变化保持待办。定期任务默认保留本地修改供复核，不自动提交、推送或部署。无变更不重拍，不批量刷新实测日期。

- 新候选指纹首次发现时 `notify=true`；未处理但内容相同的候选继续列出，不重复提醒。
- 连续三次未核实时提醒一次，持续失败不每周轰炸；恢复可读或待办撤销时重新提示。
- 无变化和首次建立比较基线默认安静；首次人工交付仍须说明覆盖与失败范围。
- 复核完成、出现需要用户处理的事项或无法运行检查时，由维护任务说明实际结果。离线或宿主不可用时不声称检查已完成。

单次失败可能来自限流、网络或动态页面，不直接修改课程为“失效”。定时配置属于当前维护者的本机任务，不会随克隆仓库复制；新维护者需另行设置。保护本地 `state.json`；迁移时应一并迁移，避免丢失未处理差异与复核历史。

## 当前覆盖与限制

配置位于 [tutorial-watchlist.js](../../maintenance/tutorial-watchlist.js)，以官方来源 ID 映射稳定的 `lessonId:section-N`。

| 主线 | 当前检查来源 |
| --- | --- |
| 网络准备 | Clash Party 稳定版发行说明、安装、上手和常见问题，共 4 份 |
| ChatGPT／Codex | 官方桌面应用、Windows、ChatGPT 文档，共 3 份 |
| WorkBuddy | Windows 安装、创建任务、任务栏、文件结果，共 4 份 |
| 豆包 | 公开聊天入口和下载页，共 2 份；动态正文可能无法读取 |

当前不是全站 46 篇课程全覆盖；新增产品需登记官方来源、最小正文要求、步骤与关键词。HTML 仅取可读的 main／article 正文，Markdown 优先使用官网明确提供的同地址版本。正文无法获取、验证页、跨站跳转、超时和超过大小限制都会保留旧记录并标为未核实。修改 URL 或提取规则须使用新来源 ID，保留旧记录，不能静默重建基线掩盖变化。

公开资料未必同步于灰度界面，正文检查不识别图片像素变化，也不检查安装包内行为、登录后页面、价格实际扣款或个人账号权限。网站纠错反馈与必要的人工抽查仍有价值；不要为了消除“未核实”去打开用户私人会话、绕过验证或降级 TLS。

## 演练与恢复

`pnpm test` 中的维护测试使用合成资料，覆盖基线→变化→定位→复核→无重复提醒、网络失败保留待办、损坏记录和并发锁，不将演练计为产品变化。

```sh
pnpm check:updates --state-dir .local/tutorial-updates-drill
```

此命令仍会读取真实官方来源，只把记录隔离；合成变化使用测试注入，不篡改真实维护基线。不要为重新提醒而删除生产记录。`state.json` 损坏时工具报错并保留原件，先备份并恢复有效副本；遗留锁须确认原进程已结束再手动处理。多文件写入中断时先重跑检查生成一致报告，不对旧报告盲目登记。
