## 内容与布局决定

### 模型指南和模型学习页

模型指南负责解释概念、按任务了解模型、找到模型系列；排名属于后续比较入口。GPT 学习页先给普通用户 ChatGPT 应用教程，再给开发者 API 入门，继续介绍任务核对、具体版本与运行设置。没有将模型当成可以下载安装到桌面的应用，也没有填入未经核实的当前版本、费用或能力分数。

手机页将桌面的旁栏目录收为“本页内容”。标题、学习入口与正文保持清楚的先后顺序。

### 全部教程和正常搜索

全部教程按学习顺序展示，保留每篇独立中文封面、内容类型和使用入口。不同课程分别承担基础概念、安装准备、桌面操作、API 接入，不能只更换产品名而复用步骤。

正常搜索以 Claude 为例，分别呈现应用、编程工具、教程、模型与路线。搜索结果能看清将进入哪一类页面；Anthropic 公司入口使用公司标识，Claude 产品入口使用产品标识。

截图中的教程摘要属于内容设计，不等于已完成产品操作实测。结果示例不虚构全站总量、热搜、阅读量或当前版本。

### 菜单与筛选

手机主导航保持学习路线、工具教程、模型指南。全部教程、实战项目、我的学习放在次级入口，避免把全部页面类型平铺到页头。

筛选面板提供教程类型、使用入口、产品三个维度。示例仅选择“软件操作”和“桌面”；应用后两项条件一致显示，结果样例为 Claude 桌面课程。“2 项”表示两个筛选条件，不表示结果数量。

### 平板

竖屏首页先显示推荐路线，再把三篇基础课并列，保留脑部、层次和气泡三种插图。课程卡片宽度增加时，正文和按钮不随画面等比例放大。

横屏阅读利用侧边目录，但正文保持可读行宽；如果正文空间不足，目录恢复折叠。图示明确标示性质，模型向软件“提供能力”的箭头方向保持正确。

## 菜单和筛选的实现约定

| 环节 | 约定 |
| --- | --- |
| 打开菜单 | 展示主、次导航分组；焦点进入菜单，背景不可误操作 |
| 关闭菜单 | 关闭按钮、Escape 均可关闭，焦点返回触发按钮；页面原滚动位置保留 |
| 点击菜单入口 | 导航到对应页面后关闭菜单，并设置新页标题与主内容焦点 |
| 打开筛选 | 以当前已经应用的条件作为本次编辑初值，不清空查询词 |
| 选择条件 | 仅更新面板内草稿；同一维度单选，不同时选择“全部”和某个具体值 |
| 关闭筛选而未应用 | 丢弃本次草稿，恢复当前已经应用的条件和结果 |
| 重置 | 清空面板内草稿条件；结果仍等到点击“应用筛选”后才改变 |
| 应用筛选 | 一次提交草稿、关闭面板、更新结果及条件条；查询词不变 |
| 移除条件标签 | 只移除对应的一项条件，更新结果并保留其余条件 |
| 清除筛选 | 移除全部已应用的筛选条件，保留查询词；恢复默认结果组织方式 |
| 筛选无结果 | 进入上一批的无结果布局，保留查询、条件和恢复入口 |
| 浏览器返回 | 恢复查询、条件和浏览位置；条件纳入可恢复的页面状态 |
| 当前目录不支持某维度 | 不显示无意义筛选项；不把教程筛选直接套到模型或公司页面 |

面板的键盘焦点、背景滚动锁定、关闭后的焦点恢复、减少动态效果等沿用上一批约定。

## 响应式约定

以下是后续实现目标，图片本身不构成测量与验收：

| 场景 | 组织方式 |
| --- | --- |
| 手机 320–767px | 主内容单栏；目录收起；筛选使用底部面板；宽表在自身容器滚动 |
| 平板竖屏参考 768px | 折叠页头主导航，首页推荐区与三课分层排列；卡片内部保持正常字号 |
| 宽度接近 900px | 根据实际可用空间切换导航；不挤压搜索、继续学习或文字 |
| 平板横屏参考 1024px | 容纳主导航；正文宽度允许时显示次级目录，否则折叠 |
| 较宽桌面 | 内容区限定最大宽度，不随屏幕无限拉长；并列板块沿用桌面稿 |

切换依据包括内容宽度、文字缩放和横竖屏，不只按设备名称判断。实现时需验证 320、390、768、1024 和常见桌面宽度，以及文字放大后菜单、卡片和正文的可用性。底部面板和固定操作区域需保留设备安全区与滚动空间。

## 下一阶段

下一阶段将这些稿整理为可点击前端原型，先贯通“首页 → 路线 → 文章 → 产品学习”和“查找 → 筛选 → 结果 → 学习”两条路径。在真实页面中补齐课末练习、收藏反馈、复制反馈、记录导入、无对应入口教程、旧链接失效和榜单历史快照等状态，依据本批及上一批约定验收。

不再为每个细小状态另开一套视觉风格；复用已确定的组件和交互规则。静态稿仍需用户审阅，具体产品教程、账号条件、原始品牌资产与榜单来源也需核对。后续原型不把设计样例包装成已经核实的最新排名或真实产品截图。
